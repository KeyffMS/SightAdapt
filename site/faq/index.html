FAQ

Common questions about SightAdapt™.

Is SightAdapt free?

Yes. SightAdapt is free and open source under the MIT License.

Does SightAdapt change application files?

No. It uses a separate Windows overlay and does not modify the target application's installed files.

Does it inject code into other applications?

No. The current alpha does not use DLL injection or write another process's memory.

Does it record or upload my screen?

The current alpha does not save or transmit captured screen content. See privacy and security for the exact boundaries.

Why does it store executable paths?

Paths are used locally to identify saved application assignments. A path can contain a Windows account or organization name, so redact it from public bug reports when necessary.

Does it work with every application?

No guarantee is made. Framework, privilege level, protected content, remote sessions and graphics drivers can affect behavior.

Can it correct only menus?

For supported native Win32 popup menus, an application can use None while an explicit menu profile is assigned. Custom-rendered menus are not separately detected.

Is SightAdapt a medical device?

The current project is a general-purpose visual-accessibility and display-personalization utility. It does not diagnose or treat medical conditions.

Why might Windows show a warning?

New or unsigned binaries may have limited Microsoft Defender SmartScreen reputation. Download only from project-controlled sources and verify the published checksum.

How do I stop all overlays?

Use Emergency disable all overlays from the notification-area menu, or exit SightAdapt.

Can I build it myself?

Yes. The repository documents the pinned .NET 8 build and publish process. Read the build instructions.

Where do I report a problem?

Use the GitHub issue tracker for reproducible defects. Do not attach private screenshots or unredacted paths. Security-sensitive reports should follow the private reporting guidance.
