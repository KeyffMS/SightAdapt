SightAdapt™ privacy

Local configuration and explicit support sharing.

The current SightAdapt alpha stores configuration locally and does not transmit captured screen content or behavioral telemetry.

What is processed locally

SightAdapt may read active-window handles, process identifiers, application display names, executable file names and full executable paths, window geometry, monitor state, saved assignments, overlay scopes and visual-profile settings. These values are used to identify the selected application and render the configured overlay.

Local storage

Settings are stored at %LOCALAPPDATA%\SightAdapt\settings.json. The file can contain application names, executable names and paths, enabled states, selected profile identifiers, overlay scopes and user-defined profile values.

Screen content and network behavior

The current release does not intentionally save screenshots, record the screen, build a screen-content history, perform content recognition or transmit captured screen content. It includes no telemetry, product analytics, advertising, remote crash reporting, automatic diagnostic upload, account, cloud synchronization or automatic update check.

Delete or reset

Exit SightAdapt and delete %LOCALAPPDATA%\SightAdapt\settings.json. Starting the application again recreates default settings.

Support data

Information reaches the project owner only when you voluntarily submit it through GitHub or another support route. Paths, screenshots, settings and logs can reveal private data. Redact usernames, organization names, private directories, unrelated windows, tokens and confidential content before sharing.

Publisher contact for submitted support data

KeyffMS / aiteracja.pl. Use the repository owner or issue tracker for public support; for non-public material, request a private communication channel before sending it.
